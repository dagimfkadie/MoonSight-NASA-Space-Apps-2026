# NASA Space Apps 2026 — Submission Readiness Checklist

This is an internal preparation checklist, not a replacement for the official challenge submission form or local-event instructions. Confirm current requirements on the official event platform before submitting.

Official event site: https://www.spaceappschallenge.org/2026/

## 1. Project identity and team

- [ ] Confirm the official team name and spelling: #MoonSightExplorers.
- [ ] Confirm every team member is correctly listed in the official Space Apps team/submission system.
- [ ] Confirm all members agree on the project description, contribution credits and final submission.
- [ ] Confirm any required parent/guardian consent or event-specific conditions for under-18 participants.
- [ ] Confirm the official challenge title and local-event requirements.

## 2. Working software

- [ ] Clone the final repository into a clean environment.
- [ ] Install dependencies using the README instructions.
- [ ] Launch the Streamlit application successfully.
- [ ] Test each tab using available data and valid user inputs.
- [ ] Confirm error messages are understandable when downloads or API calls fail.
- [ ] Confirm CSV exports contain the expected columns and units.
- [ ] Confirm no API credentials or private information are exposed.
- [ ] Record the exact Git commit used for the submitted demo.

## 3. Data and scientific integrity

- [ ] Verify NASA LOLA source URLs and product descriptions.
- [ ] Record the metadata of at least one real downloaded GeoTIFF.
- [ ] Verify the full CRS/reference frame against NASA's authoritative metadata.
- [ ] Verify product units and NoData behavior.
- [ ] Test live JPL Horizons requests with a documented lunar coordinate.
- [ ] Compare at least one Horizons result with an independently configured reference query.
- [ ] Clearly label sample statistics and downsampled visualizations.
- [ ] Do not describe geometric elevation as terrain-clear visibility.
- [ ] Do not claim landing safety, mission feasibility, power availability or communications capability.
- [ ] Update scientific validation status with actual evidence; do not mark pending checks as passed.

## 4. Documentation and attribution

- [ ] Review README and User Guide against the final app.
- [ ] Review Project Overview and Scientific Methodology.
- [ ] Review Data Provenance and Scientific Validation.
- [ ] Review AI Assistance Disclosure with all contributors.
- [ ] Credit NASA, JPL, libraries, datasets and other third-party materials accurately.
- [ ] Confirm repository license and contributor agreement.
- [ ] Confirm no NASA endorsement or affiliation is implied.

## 5. Demo preparation

- [ ] Prepare a short explanation of the problem, approach and current prototype.
- [ ] Demonstrate one terrain product and explain its source and units.
- [ ] Demonstrate region comparison without claiming that it ranks landing sites.
- [ ] Demonstrate Sun/Earth geometry using a documented coordinate and explain its limitations.
- [ ] Prepare a fallback recording or screenshots in case live external services are unavailable.
- [ ] Ensure screenshots and video do not show secrets, private messages or personal information.
- [ ] Check official rules for required video, images, links, language, duration and file formats.

## 6. Final submission

- [ ] Read the official submission instructions immediately before submitting.
- [ ] Confirm the deadline and timezone displayed for the team's event.
- [ ] Complete every required field in the official submission form.
- [ ] Verify all links work for reviewers without requiring private access.
- [ ] Verify repository visibility and that the intended commit is on the default branch.
- [ ] Submit before the official deadline.
- [ ] Save the submission confirmation and final submitted project text.
